# tripla 価格モニタリングダッシュボード

tripla（自社予約）と主要OTA（楽天トラベル / じゃらん / 一休.com など）の**実質販売価格**（表示価格 − 即時割引 − ポイント還元相当額）を日毎に比較し、triplaが最安値（最低価格保証）を維持できているかを一目で確認するためのプロトタイプです。

> **注意**: このコードはNode.jsが利用できないサンドボックス環境で作成されたため、`npm install` / `npm run dev` はまだ実行・検証されていません。お手元の環境（Node.js 18以降推奨）でセットアップしてください。

## セットアップ

```bash
npm install
npm run dev
```

`http://localhost:3000` を開くとダッシュボードが表示されます（初回はサンプルデータで表示されます）。

## 主な機能

- **対象プラン固定**: 比較対象は「【2階】スタンダードダブル（朝食付き）」／大人2名（2名1室合計金額）に固定されています。プラン選択UIはありません。
- **対象月選択**: ヘッダーの「対象月」ドロップダウンで年月を選ぶと、その月の1日〜末日が自動的にテーブルへ一括表示されます。まだデータの無い月を選ぶと、確認しやすいようデモ値で自動補完されます（実データをCSVアップロードすれば上書きされます）。
- **日別価格比較テーブル**: 日付 × OTA のマトリクスで、実質価格・表示価格（割引がある場合は取り消し線）・割引内容（Google Hotels由来の場合は元の表記もそのまま表示）を表示。最安セルは緑、TRIPLAが最安値を逃している日は赤でハイライトします。左端の日付列は横スクロール時も固定表示されます。空室が無い（満室）ことが確認できたセルはグレーの「満室」バッジ表示になり、最安値判定・価格逆転アラートの計算からは除外されます。
- **差額列**: `TRIPLA実質価格 − 他社最安実質価格` と「⚠ 価格逆転 / ✓ 最安値維持」のステータスを1列にまとめて表示します。
- **価格逆転アラートフィルター**: 「⚠ 価格逆転日のみ表示」トグルで、TRIPLAが他社より高い日だけを抽出します。
- **CSV入出力**: 「この月のCSVを出力」で表示中の月のデータをそのままCSVとして書き出し、「CSVアップロード」で一括取り込みできます（未知のOTAは自動的に列として追加されます）。
- **手動編集**: 各セルをクリックすると表示価格・割引種別（円引 / %還元）・割引額をその場で編集できます。
- **サマリーカード**: 対象月の対象日数、最安値維持日数、価格逆転日数、平均差額を表示します。
- **Google Hotels連携（Chrome拡張）**: [chrome-extension/](chrome-extension/) の拡張機能が `/api/prices` にPOSTすると、ダッシュボードが4秒間隔のポーリングで自動的に取り込み、該当セルを更新してヘッダーに受信ステータスを表示します。詳しくは [chrome-extension/README.md](chrome-extension/README.md) を参照してください。

## CSVフォーマット（ロング形式）

プランは固定のため列には含みません。1行 = 1日 × 1OTA です。

```
date,otaId,otaName,price,discountType,discountValue,status
2026-10-01,tripla,TRIPLA（自社予約）,22000,fixed,0,
2026-10-01,rakuten,楽天トラベル,22500,percent,2,
2026-10-01,jalan,じゃらん,22300,percent,1,
2026-10-01,ikyu,一休.com,22800,fixed,500,
2026-10-02,rakuten,楽天トラベル,,,,full
```

- `discountType` は `percent`（ポイント還元率など、%指定）または `fixed`（一休.comの即時利用ポイントなど、円指定）。
- `otaId` が既存OTA一覧に無い場合は自動的に新しいOTA列として追加されます（`otaName` があれば表示名に利用）。
- アップロードした日付は、対象月フィルターの`date.startsWith("YYYY-MM")`で自動的に該当月に振り分けられます。同じ日付・OTAの行を再アップロードすると、その値で上書きされます。
- `status` 列に `full`（大文字小文字は問わない）を指定すると、`price`/`discountType`/`discountValue` は無視され「満室」として取り込まれます。空欄の場合は通常の価格行として扱われます（既存のCSVもそのままアップロード可能です）。

## ディレクトリ構成

```
app/                      Next.js App Router のエントリポイント
app/api/prices/route.ts   Chrome拡張からのPOST受信 / ダッシュボードのポーリング用GET（CORS対応）
components/ui/            汎用UIプリミティブ（Button, Cardなど）
components/pricing/       ダッシュボード本体（テーブル・フィルター・セル編集・受信ステータス表示など）
lib/types.ts              型定義（OTA設定・価格エントリ・日別レコード）
lib/pricing.ts            実質価格計算・最安値判定・差額分析ロジック
lib/csv.ts                CSVパース / マージ / テンプレート生成
lib/sample-data.ts        デモ用サンプルデータ生成
lib/server-store.ts       /api/prices が受信したデータの永続ストア（Redis。未設定時はインメモリにフォールバック）
chrome-extension/         Google Hotelsから価格を取得するChrome拡張（別途 chrome-extension/README.md 参照）
```

## データの永続化（Redis）

`/api/prices` が受信したデータは [lib/server-store.ts](lib/server-store.ts) を通じて保存されます。**環境変数 `REDIS_URL` が設定されていればそこに永続保存され、未設定の場合はNext.jsプロセスのメモリ上に一時保存されるだけ**（再デプロイ・コールドスタートで消えます）。半年単位でデータを蓄積したい場合は、以下の手順でRedisを有効にしてください（デプロイ済みのVercelプロジェクトのダッシュボードで行う作業です。このリポジトリ側の追加作業は不要）。

1. Vercelのプロジェクトダッシュボード →「Storage」タブを開く
2. 「Create Database」から Redis 系のストアを作成し、プロジェクトに接続する（Connect Project）
3. 接続すると環境変数が自動追加される。実機確認では `REDIS_URL`（`redis://` または `rediss://` 形式の接続文字列）が付与された（プロバイダーによっては `KV_REST_API_URL` / `KV_REST_API_TOKEN` のREST API形式になることもあり、本コードはどちらの形式でも `REDIS_URL` を優先的に使う）
4. 環境変数が反映されるよう、プロジェクトを**再デプロイ**する（Deployments タブから Redeploy、または何かpushする）
5. `GET /api/prices` のレスポンスに含まれる `kv` フィールド（`connected` / `pingOk` / `matchingEnvKeys`）で、実際に接続できているかを確認できる（接続文字列そのものは含まれない）

これで `/api/prices` へのPOSTは既存データを消さずにupsert（追記・更新）され、Vercelの再デプロイやサーバーレス関数のコールドスタートをまたいでもデータが保持されます。Redis未設定のままでも動作はしますが、その場合は再デプロイのたびにデータがリセットされる点にご注意ください。
